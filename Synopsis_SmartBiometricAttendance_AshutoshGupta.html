1. INTRODUCTION

The Smart Biometric Attendance System — developed under the project name stuatten — is a comprehensive, Android-first, web-enabled academic attendance management platform designed specifically for AKTU-affiliated engineering colleges. The system was conceived to permanently eradicate the longstanding problem of proxy attendance, where a student fraudulently marks attendance on behalf of an absent classmate, which is a critical threat to academic integrity across technical institutions in India.

Traditional attendance systems — whether paper-based roll-call registers or basic OTP/RFID-based digital systems — rely solely on a student's unverifiable claim of presence, making them trivially susceptible to manipulation. The proposed system addresses this through a five-layer anti-proxy verification engine that combines: (1) GPS geofencing with Haversine-formula distance calculation, (2) Android biometric authentication (fingerprint and face recognition), (3) session-specific QR code token validation, (4) real-time profile photo cross-verification, and (5) cryptographic device binding — ensuring that only the legitimate student, physically present within the classroom boundary, can successfully mark attendance.

The platform serves three distinct user roles with dedicated interfaces: a Student Portal, a Teacher Dashboard, and an Admin Control Panel. Each interface is precisely tailored to the responsibilities and access privileges of the respective user. The system is built on a modern full-stack JavaScript architecture, making it deployable as an Android APK and simultaneously accessible via any standard web browser, without requiring separate software installation.

Technology Domain

This project lies at the intersection of Mobile Computing, Web Technologies, Biometric Information Systems, and IoT-based Smart Campus Solutions. It integrates client-side cross-platform mobile and web application development with a server-side REST API architecture backed by a cloud-capable NoSQL database.

Technology Stack
  • Frontend (Mobile App): React Native with Expo SDK 51 — Android & web deployment from a single codebase
  • Frontend (Web Browser): Pure HTML5, CSS3, and Vanilla JavaScript — Single Page Application (SPA)
  • Backend: Node.js v18 with Express.js — RESTful API server with 30+ endpoints
  • Database: MongoDB with Mongoose ODM — 9 document collections with offline fallback
  • Authentication: JSON Web Tokens (JWT) with bcrypt password hashing, 24-hour token expiry
  • Location Services: GPS with Haversine-formula geofencing (configurable radius, default 50 m)
  • Biometrics: Android Biometric API via expo-local-authentication library
  • Export: SheetJS (XLSX) for Excel reports, PDFKit for PDF reports
  • Security: Helmet.js HTTP headers, express-rate-limit, CORS, device-ID binding, audit logging

Important Technical Terms
  • Biometric Authentication: Identity verification using unique physiological traits (fingerprints, facial geometry) stored on the user's device — impossible to duplicate or transfer to another person.
  • Geofencing (Haversine Formula): A virtual geographic boundary defined by GPS coordinates and a radius (50 m). The Haversine formula calculates the great-circle distance between two GPS points on Earth's spherical surface with millimetre-level accuracy.
  • JWT (JSON Web Token): A compact, URL-safe, cryptographically signed token used for secure stateless authentication between the mobile/web client and the Express API server.
  • RBAC (Role-Based Access Control): Permissions are assigned based on role (STUDENT / TEACHER / ADMIN), enforced server-side by a JWT middleware on every protected API route.
  • QR Code Session Token: A cryptographically unique token embedded in a QR code, generated per attendance session by the teacher. Students must validate this token to prove attendance at a specific class.
  • Device Binding: A security mechanism that ties each user account to a unique hardware device identifier (boundDeviceId), preventing simultaneous logins from multiple devices or session sharing.
  • REST API: A stateless, HTTP-based communication architecture used for all 30+ client-server interactions, with standard HTTP verbs (GET, POST, PUT, DELETE) and JSON payloads.
  • NoSQL / MongoDB: A document-oriented database that stores data in flexible, JSON-like BSON documents — ideal for dynamic schemas such as student profiles, attendance sessions, and audit logs.
  • Offline Fallback Mode: A resilience mechanism where the system automatically switches to in-memory mock data when MongoDB is unreachable, ensuring zero downtime during network outages.
  • AKTU Roll Number: A 13-digit unique identifier issued by Dr. A.P.J. Abdul Kalam Technical University (e.g., 2100270100001), used as the primary student key throughout the system.
  • Defaulter: Per AKTU regulations, a student whose overall attendance falls below 75% is classified as a defaulter and may be barred from appearing in semester examinations.

The stuatten system is fully compatible with AKTU's 13-digit roll number format and academic calendar structure. The 75% minimum attendance requirement mandated by AKTU is hard-coded into the analytics engine, with real-time defaulter identification and automatic student notification features built in as core functionality — not optional add-ons.

2. STATEMENT OF PROBLEM WITH OBJECTIVES
Statement of Problem

In AKTU-affiliated engineering colleges, a minimum of 75% attendance is mandated for examination eligibility. However, existing attendance systems — both manual (paper registers) and basic digital systems — suffer from the following critical limitations:

  • Proxy Attendance Fraud: Students routinely mark attendance for absent classmates in paper registers or share OTPs/QR images via messaging apps, completely defeating the attendance policy.
  • No Physical Location Verification: No existing low-cost system verifies that the student is actually inside the classroom at the time of marking.
  • No Biometric Identity Confirmation: There is no mechanism to confirm that the person marking attendance is the registered account holder, not a friend or proxy.
  • Manual Data Management Overhead: Teachers spend 5–10 minutes per class on roll calls, reducing valuable instructional time and introducing human data-entry errors.
  • Delayed Defaulter Detection: Attendance reports are manually compiled weekly or monthly, causing significant delay in identifying defaulter students who could have corrected their attendance in time.
  • No Tamper-Proof Audit Trail: Traditional systems provide no cryptographic record of who marked attendance, when, from which location, or using which device.
Objectives of the Proposed System
  1. To prevent proxy attendance by implementing a five-layer anti-spoofing verification system — GPS geofencing (50-metre classroom radius), biometric authentication (fingerprint / face recognition), QR code session token validation, real-time profile photo cross-verification, and cryptographic device binding — making proxy attendance practically impossible.
  2. To fully digitise and automate the attendance workflow — from teacher session creation with QR code generation to student attendance marking and real-time roster updates — reducing teacher workload to under 60 seconds per session and eliminating paper registers completely.
  3. To provide real-time, subject-wise attendance analytics with automatic percentage calculation, instant identification of AKTU defaulter students (below 75%), and real-time push notifications to students upon every attendance status change.
  4. To implement a secure, role-based access control system with separate dashboards for Students, Teachers, and Administrators, enforced by JWT-based authentication, bcrypt password hashing, device binding, rate limiting (300 req/15 min), and a tamper-proof audit log of all system events.
  5. To ensure universal accessibility across platforms by delivering the system simultaneously as an Android mobile application (React Native + Expo) and as a web browser application (HTML/CSS/JS SPA) accessible at a single server URL — ensuring zero installation barrier for all users.
  6. To generate exportable official attendance reports in Excel (.xlsx) and PDF formats for any session at the click of a button, and to maintain full AKTU 13-digit roll number compatibility for seamless integration with university record systems.

Note: A minimum of 4 objectives have been provided (6 objectives given above).

3. LITERATURE SURVEY

The following is a review of significant prior work done by different authors, researchers, and developers related to biometric authentication, GPS-based attendance systems, and QR code-based attendance management. The research gap addressed by the stuatten system is identified at the end of this section.

1. Jain, Ross & Prabhakar (2004) — "An Introduction to Biometric Recognition," published in IEEE Transactions on Circuits and Systems for Video Technology — established the foundational framework for biometric identity verification. The authors demonstrated that fingerprint and facial recognition provide the highest accuracy-to-cost ratio for large-scale identity systems. This work provides the theoretical basis for the biometric authentication layer in stuatten.

2. Mane & Gaikwad (2019) — "Smart Attendance System Using RFID and GPS" — proposed an RFID-based attendance system with GPS tracking. However, RFID cards can be physically handed to another person for proxy use without detection. stuatten resolves this by replacing RFID cards with on-device biometric data (fingerprint/face), which cannot be transferred or shared.

3. Chaudhari, Sawant & Jaiswal (2020) — "Face Recognition Based Attendance System Using OpenCV" — presented a server-side face recognition system for classroom use. The limitation was the requirement for a fixed camera and dedicated server infrastructure, making it expensive for budget-constrained rural colleges. stuatten eliminates this dependency by using the student's own smartphone camera with on-device biometric APIs, requiring no additional hardware.

4. Gupta & Sharma (2021) — "QR Code Based Attendance Management System" — proposed a QR code scanning attendance system. However, the critical vulnerability identified was that a student could photograph the QR code and share it via WhatsApp with an absent classmate. stuatten solves this by combining QR token validation with GPS geofencing — the student must be physically within 50 metres of the classroom to successfully validate the QR token.

5. Patil, Kulkarni & Deshmukh (2022) — "Android-Based Student Attendance System with GPS Location Verification," IJERT — validated the feasibility of GPS-based geofencing for classroom boundary enforcement in a mobile app. stuatten extends this approach with four additional verification layers and a complete teacher-controlled session lifecycle (create → QR → live roster → export → close), which was entirely absent in their system.

Research Gap Identified

A systematic review of the above literature reveals that no existing system integrates all five verification layers (GPS + Biometric + QR + Device Binding + Photo Verification) in a single unified platform, combined with offline resilience, exportable reports, an admin control panel, and simultaneous browser-based access. This multi-layer, platform-agnostic, offline-capable approach is the unique and original contribution of the stuatten system.

4. EXPECTED OUTCOME / SCOPE OF THE PROJECT
Expected Outcomes
  • Near-zero proxy attendance: The five-layer verification stack makes proxy attendance practically impossible — a fraudster would simultaneously need the legitimate student's smartphone, biometric data (fingerprint/face), and physical presence within the classroom.
  • 100% digital, tamper-proof records: All attendance events are stored in MongoDB with timestamps, GPS coordinates (latitude/longitude), biometric verification status, device ID, and QR token — creating a complete cryptographic audit trail.
  • Instant defaulter detection: Students falling below 75% overall attendance receive automatic notifications, enabling early corrective action before they lose examination eligibility under AKTU regulations.
  • Significant teacher time savings: Attendance marking time reduces from 5–10 minutes (manual roll-call) to under 60 seconds per session using the QR-based system with live roster auto-update.
  • One-click downloadable reports: Teachers can generate official Excel (.xlsx) and PDF attendance reports for any session instantly, eliminating manual compilation and data-entry errors.
  • Universal access: The system works on Android phones (Expo app) and simultaneously in any web browser (Chrome, Edge, Firefox, Safari) at http://localhost:5000, with no separate installation required.
Key Features of the Delivered System
  • Student: 5-step attendance marking flow (Session Select → GPS Check → Biometric → Photo Verify → Submit)
  • Teacher: Full session lifecycle (Create + QR Code → Live Roster → Manual Toggle → Close → Export Excel/PDF)
  • Admin: Analytics dashboard, defaulter list, photo approval workflow, security audit logs, student/teacher CRUD
  • Cross-platform deployment: Android APK (via Expo EAS Build) + Web Browser SPA (http://localhost:5000)
  • Offline-resilient: Automatic in-memory fallback activates when MongoDB is unreachable — zero downtime
  • Dark / Light mode toggle with localStorage theme persistence across sessions
Intended Users

The system is designed for AKTU-affiliated engineering and technology colleges across Uttar Pradesh. Primary users include undergraduate B.Tech students, faculty members, and department administrators. The system architecture scales from 100 students in a single department to 10,000+ students across a multi-department institution, with MongoDB Atlas cloud deployment.

Scope for Future Improvements
  • Direct API integration with AKTU's official ERP portal for automatic data synchronisation and examination eligibility updates
  • AI/ML-based server-side face recognition with liveness detection (anti-photo-spoof) using OpenCV and DeepFace
  • SMS and WhatsApp gateway notifications to parents for defaulter alerts and attendance summaries
  • Machine learning-based predictive analytics to identify students at risk of becoming defaulters weeks in advance
  • Blockchain-based immutable attendance ledger for tamper-proof verification by the AKTU examination board
  • Multi-college SaaS deployment on MongoDB Atlas + Railway/Render with college-specific subdomain routing
