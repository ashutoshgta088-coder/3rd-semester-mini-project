ABSTRACT

In engineering colleges affiliated with Dr. A.P.J. Abdul Kalam Technical University (AKTU), maintaining a minimum classroom attendance of 75% is mandatory for semester examination eligibility. However, legacy attendance mechanisms — such as manual roll-call registers and static QR codes — suffer from severe systemic flaws including proxy attendance fraud, 15–20% lecture hour wastage (taking 8 to 12 minutes per class), and delayed manual defaulter calculations.

This mini project presents Stuatten, a Bluetooth Low Energy (BLE) and biometric-assisted smart attendance management platform engineered specifically for AKTU institutions. The system utilizes a five-layer verification pipeline:

  • BLE Beacon Broadcasting: The teacher's smartphone advertises a temporary, rotating 128-bit UUID session token using non-connectable BLE peripheral mode, eliminating one-to-one pairing bottlenecks.
  • Smartphone Biometrics: FIDO2 / WebAuthn passkey authentication utilizing native device fingerprint scanners and front cameras.
  • Haversine GPS Geofencing: Micro-location boundary check (≤50m) ensuring physical classroom presence.
  • Instant Real-Time Synchronization: Bidirectional Socket.IO WebSocket events updating the teacher's live roster instantaneously without page reload.
  • AKTU Automated Defaulter Tracking: Instant <75% attendance calculations, attendance history, and one-click UTF-8 BOM Excel/CSV reports.

The software architecture leverages a React.js + Vite responsive frontend, an Express.js / Node.js REST server, and MongoDB Atlas ODM with an offline in-memory store. Empirical evaluation demonstrates complete classroom convergence in < 45 seconds with zero proxy vulnerability.

CHAPTER 1: INTRODUCTION
1.1 Background

Academic discipline in professional engineering institutions under Dr. A.P.J. Abdul Kalam Technical University (AKTU) places fundamental emphasis on regular classroom engagement. Under AKTU academic ordinance, every student enrolled in Bachelor of Technology (B.Tech) courses must attain at least 75% attendance in all registered theory lectures and laboratory courses to qualify for semester examinations.

Despite this crucial requirement, attendance monitoring across technical colleges in Uttar Pradesh has remained predominantly manual. Faculty members physically carry paper registers, reciting roll numbers one-by-one. In a standard class size of 60 to 70 students, this repetitive routine takes 8 to 12 minutes out of every 50-minute lecture hour, resulting in a staggering 15% to 20% loss of actual syllabus delivery time.

1.2 Problem Statement

Conventional paper roll calls and basic computerized methods suffer from fatal weaknesses:

  • Proxy Attendance Vulnerability: Absent students routinely ask friends to answer during roll call or share static QR code photos through mobile messaging applications.
  • Administrative Overhead: Faculty spend hours compiling weekly sheets, counting totals, and calculating percentages manually.
  • High Cost of Biometric Wall Scanners: Fixed biometric readers cost upwards of ₹20,000 per room and cause hallway congestion before lectures.
  • Delayed Defaulter Identification: Defaulter lists are compiled only once a month, preventing timely academic warnings.
1.3 Objectives
  1. To eliminate proxy attendance using a 5-layer multi-factor presence verification pipeline (BLE + Biometric + Geofence).
  2. To automate attendance logging to under 45 seconds per lecture without external hardware.
  3. To provide real-time live synchronization using WebSockets (Socket.IO) updating the teacher roster instantly.
  4. To automate AKTU 75% percentage tracking and provide one-click Excel/CSV report exports.
1.4 Scope of the Project

The project encompasses a cross-platform progressive web client (React 18 + Vite), an Express.js / Node.js REST server, MongoDB database models, and Android Kotlin BLE services. The scope covers role-based access for Students, Teachers, and Department Admins across technical institutions.

1.5 Organisation of the Report

This report is structured into seven chapters: Chapter 2 reviews literature and existing systems; Chapter 3 outlines system analysis, feasibility, and architecture; Chapter 4 presents implementation and algorithms; Chapter 5 details testing strategies; Chapter 6 evaluates performance results; and Chapter 7 concludes the project with future enhancement scope.

CHAPTER 2: LITERATURE REVIEW / EXISTING SYSTEM
2.1 Review of Related Work

Over the past decade, various technological approaches have been explored to automate student attendance:

  • RFID-Based Systems: Require RFID cards issued to students and readers near doors. However, buddy swiping (where one student carries multiple cards) completely defeats its security.
  • Fingerprint Wall Terminals: Highly accurate, but throughput is slow (1 student every 5–8 seconds), leading to long queues outside classrooms.
  • Static QR Code Scanning: Fast, but vulnerable to screen sharing across WhatsApp groups, enabling remote marking from hostels.
  • Facial Recognition Cameras: Computationally intensive, sensitive to classroom lighting conditions, and raises student privacy concerns.

2.3 Gaps Identified

Existing solutions either compromise on security (paper registers, QR codes) or on convenience and cost (expensive wall-mounted biometric scanners). No single existing platform integrates Bluetooth Low Energy signal detection with native smartphone biometric passkeys and geofencing.

2.4 Proposed System

Stuatten bridges these gaps by transforming everyday student and faculty smartphones into verified attendance terminals. By advertising an ephemeral session identifier over BLE and validating submissions server-side with GPS coordinates and WebAuthn biometric challenges, the platform achieves zero-cost, uncompromised attendance verification.

CHAPTER 3: SYSTEM ANALYSIS AND DESIGN
3.1 Requirement Analysis
3.1.1 Functional Requirements:
  • User Authentication: Secure self-registration and login with 24-hour JWT tokens.
  • Session Lifecycle: Teacher can start, broadcast, monitor, and close attendance sessions.
  • Multi-Factor Verification: BLE beacon scan, GPS geofence match, and biometric authentication.
  • Real-Time Roster: Live WebSocket update on teacher dashboard as students mark attendance.
  • Reporting: Automatic AKTU 75% threshold analysis and Excel/CSV export.
3.1.2 Non-Functional Requirements:
  • Security: Encrypted passwords (bcrypt salt rounds: 10), HTTPS, CORS protection, rate-limiting.
  • Performance: Sub-second API responses (<180ms) and WebSocket broadcast (<50ms).
  • Scalability: Concurrent handling of 100+ simultaneous submissions per classroom.
  • Reliability: Offline in-memory fallback store ensuring zero interruption during cloud outages.
3.2 Feasibility Study
  • Technical Feasibility: The technology stack (React, Node, BLE, WebAuthn) utilizes mature, open-source standards.
  • Economic Feasibility: 100% cost-free implementation leveraging students' existing smartphones (BYOD).
  • Operational Feasibility: Intuitive 5-step wizard requiring under 30 seconds of student effort.

CHAPTER 4: IMPLEMENTATION
4.1 Module Description
  • Authentication Module: Role-based login and registration supporting 13-digit AKTU roll numbers and faculty IDs, backed by bcrypt password hashing.
  • Session Controller: Allows educators to schedule, start, monitor, and auto-expire attendance sessions.
  • Attendance Verification Module: Validates student location coordinates against classroom center and checks WebAuthn credentials.
  • Live Sync Module: Emits real-time Socket.IO events to all connected clients in the teacher's session room.
  • Export Engine: Generates formatted spreadsheets in UTF-8 BOM CSV format for direct opening in Microsoft Excel.
